# AI Discovery Phase One Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a reliable research-plan preflight and recovery flow so AI Discovery explains what it understood, blocks unsupported execution before task creation, preserves work through login, and offers an executable alternative.

**Architecture:** Add a pure research-planning domain module backed by a centralized metric registry, expose it through an authenticated plan endpoint, and require task creation to revalidate the submitted plan constraints. The React entry page becomes a small state machine composed from focused plan, progress, and recovery components; pending plans are persisted in session storage through authentication.

**Tech Stack:** Python 3.12, FastAPI, Pydantic, SQLite-backed ProductStore, React 18, TypeScript, React Router, Vitest, Testing Library, pytest.

**Spec:** `docs/superpowers/specs/2026-08-25-ai-discovery-orchestrator-design.md`

## Global Constraints

- Phase one supports executable constraints for valuation, dividend yield, and market value using currently available market rows.
- Cash flow, growth, profitability quality, industry comparison, and historical percentile conditions must be recognized but marked `unavailable`; they must never silently become name or industry search.
- Authentication redirects must preserve the question, template, parsed conditions, and suggested executable version in session storage.
- The backend is authoritative: task creation must validate constraints again even when a plan was generated by the server.
- Desktop wide-screen UI is the target; mobile redesign is outside this phase.
- Existing research results and previously saved tasks remain readable without migration.
