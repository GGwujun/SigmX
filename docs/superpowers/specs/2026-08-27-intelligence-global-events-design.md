# 情报搜索与全球事件数据架构设计

日期：2026-08-27

## 1. 目标

将 Web 情报产品从“华尔街见闻 RSSHub + Bing 搜索结果列表”升级为可追溯的多源财经情报系统，并增加独立的“全球事件”频道。新闻、公告和政策是原始情报；全球事件是多条原始情报经实体识别、去重、聚类和验证后形成的持续更新对象。

系统服务于信息发现和 AI 投研，不直接产生交易指令。预测市场只作为事件预期信号，不能替代事实来源。

## 2. 产品边界

Web 情报产品包含两个独立页面：

- **情报搜索**：搜索新闻、公告、政策和产业信息，回到原文核验。
- **全球事件**：展示已聚合的地缘、宏观、产业、公司和灾害事件及其市场影响链。

文章详情关联所属事件；事件详情展示支撑文章、官方来源、演化时间线、关联市场与资产。两类对象都可以携带证据上下文进入 AI 发现。

## 3. 数据源分层

### 3.1 一级：官方事实源

- A 股：巨潮资讯、上交所、深交所、北交所公告。
- 港股：港交所披露易。
- 美股：SEC EDGAR 最新申报、公司申报检索和结构化披露 RSS。
- 国内政策：国务院、人民银行、证监会、国家统计局、发改委、工信部。
- 海外政策：Federal Reserve、US Treasury、SEC、ECB、IMF、World Bank。
- 上市公司官网公告与投资者关系页面。

官方源用于确认事实，拥有最高来源等级。接入必须遵循各站点服务条款、速率限制和内容授权。

### 3.2 二级：财经媒体与快讯

- 国内：财联社、新浪财经、东方财富、华尔街见闻。
- 海外：优先接入有公开 RSS/API 或已有合法授权通道的 Reuters、AP、BBC、CNBC 等来源。
- Bing 仅作检索召回补充，不能单独提升事件可信度。

### 3.3 三级：全球事件与预期信号

- GDELT DOC、Event/GKG：全球报道发现、地点和参与方提取、报道热度及事件聚类候选。
- Polymarket、Kalshi：事件概率、24 小时变化和市场关注度。
- 后续专项源：自然灾害、制裁、航运、能源和商品公开数据。

GDELT 自动分类和预测市场概率都不是事实裁决。事件只有获得可追溯文章或官方来源支撑后才能公开展示。

## 4. 统一来源适配器

每个来源实现相同的 `IntelligenceSourceAdapter`：

- 来源标识、名称、等级、市场和语言；
- 拉取能力：默认流、关键词搜索或增量游标；
- 标准化输出；
- 速率、超时、重试和缓存策略；
- 健康检查和错误分类；
- 内容许可策略：正文可存、仅摘要或仅元数据。

适配器失败相互隔离。聚合服务返回每个来源的状态，不能用空列表掩盖上游失败。

## 5. 数据模型

### 5.1 `intelligence_articles`

- `id`、规范化标题、摘要、正文状态；
- 原文 URL、规范化 URL、来源及来源等级；
- 发布时间、抓取时间、语言和地区；
- 内容类型：新闻、公告、政策、研报摘要或快讯；
- 主题、实体、公司、证券和行业关联；
- URL、标题和内容指纹；
- 授权、缓存、保留和删除时间；
- 原始来源 ID 与原始元数据。

### 5.2 `global_events`

- `id`、规范化标题、摘要和事件类型；
- 地区、参与方、实体和关键词；
- 首次发生、最近更新、预计结束和当前状态；
- 重要性、可信度、报道热度和新鲜度；
- 影响市场、行业、公司、证券、商品与汇率；
- 影响方向、影响链和待验证假设；
- 支撑文章数、官方来源数和事件版本。

### 5.3 关联表

- 事件—文章：关联强度、是否关键证据、首次/最近关联时间；
- 事件—资产：资产类型、影响方向、影响强度和解释；
- 事件信号：Polymarket/Kalshi 概率、变化、成交量和更新时间；
- 事件版本：每次标题、摘要、状态、影响和证据集合变化。

## 6. 采集、去重与事件聚合

处理流水线：

1. 按来源增量采集并保留原始来源 ID。
2. 标准化 URL、时间、语言、来源和正文状态。
3. 按规范化 URL、标题指纹、内容指纹三级去重。
4. 提取公司、证券、行业、国家、地区、人物、组织和商品实体。
5. 根据实体重合、地点、时间窗口、事件类型和语义相似度生成事件候选。
6. 官方来源确认事实，媒体补充进展，多源交叉验证。
7. 更新事件及版本轨迹，避免同一事件重复生成。
8. 建立事件与市场、行业和标的之间的可解释影响链。

聚类不确定时保留为独立候选，不强行合并。事件合并和拆分操作必须可在运营后台审计。

## 7. 排序与质量

情报默认排序分：相关性 30%、时效性 20%、来源可信度 20%、市场影响 20%、多源确认 10%。搜索时相关性权重可以提高，但不能掩盖来源等级。

全球事件排序综合重要性、可信度、新鲜度、报道热度、市场覆盖面和状态变化。预测市场信号只影响“市场关注度”，不提高事实可信度。

页面必须显示来源、发布时间、数据状态和原文链接。时间未知、来源未知或无可访问证据的内容不得进入高优先级结果。

## 8. 缓存与保留

- 默认快讯流缓存 2–5 分钟。
- 关键词搜索缓存 10 分钟。
- 官方公告和政策缓存 15 分钟。
- 活跃全球事件每 5–15 分钟刷新。
- 外部源失败时允许使用 24 小时内缓存，并明确标记 `stale_cache`。
- 普通原始新闻保留 90 天。
- 重要事件证据、被 AI 研究引用或用户收藏的文章长期保留元数据和证据快照。
- 全球事件与版本轨迹长期保存。
- 无正文存储授权时只保留摘要、元数据、指纹和原文链接。

清理任务按来源许可和保留策略执行，不能删除仍被研究结果引用的证据。

## 9. API

情报 API 支持关键词、类型、市场、行业、来源等级、时间范围、语言和分页；响应包含真实来源健康状态、缓存状态和降级信息。

全球事件 API 支持类别、地区、影响市场、重要性、状态、时间范围和分页。事件详情返回时间线、支撑证据、关联资产、影响链和预测市场信号。

新增文章/事件转研究上下文接口，向 AI 发现传递稳定对象 ID 和证据快照，而不是只传标题字符串。

现有 `/api/public/intelligence` 保持兼容，并迁移到统一聚合服务。现有客户端 `/events` 接口暂时保留，Web 不直接依赖其旧数据结构。

## 10. Web 交互

### 10.1 情报搜索

- 筛选：全部、公告、政策、公司、行业、宏观、海外；
- 来源等级、市场和发布时间筛选；
- 详情侧栏展示摘要、原文、相关事件、关联标的和来源状态；
- “转为 AI 研究”携带文章、事件和证券上下文。

### 10.2 全球事件

- 独立顶部导航入口和页面；
- 分类：地缘、宏观政策、产业科技、公司事件、自然灾害、能源商品；
- 事件列表/时间线展示重要性、可信度、热度、状态和影响市场；
- 详情展示演化时间线、多源证据、预测市场概率、关联资产和影响链；
- 支持关注事件、查看更新和转为 AI 研究；
- 不直接展示买入卖出建议。

## 11. 运营后台

增加情报数据管理模块：来源配置与健康、最近成功时间、失败率、限流、抓取数量、重复率、正文授权状态、事件候选、事件合并/拆分、错误重试和数据清理状态。

敏感凭据只保存在服务端配置中，不通过页面接口回传明文。

## 12. 错误与降级

- 单一来源失败不阻断其他来源。
- 主来源全部失败时返回结构化错误；存在有效缓存时返回缓存和明确警告。
- GDELT 不可用时仍展示已确认事件和官方源更新，但标记全球覆盖受限。
- 预测市场不可用时隐藏概率模块，不影响事件事实展示。
- AI 摘要失败时展示原始标准化内容，不能生成占位结论。

## 13. 实施阶段

1. 建立数据库迁移、标准模型、来源适配器和聚合服务。
2. 迁移现有华尔街见闻/Bing，并接入新浪、东方财富及国内官方公告/政策首批源。
3. 接入 GDELT，完成事件候选、聚类、版本和证据关系。
4. 将 Polymarket/Kalshi 改造成事件附属信号。
5. 改造情报搜索 API、缓存、去重和排序。
6. 新增 Web 全球事件页面和详情。
7. 接通 AI 发现稳定上下文。
8. 增加运营后台来源健康和事件治理。

每阶段保留现有情报页面可用，使用兼容接口渐进迁移。

## 14. 测试与验收

- 来源适配器契约、超时、重试、限流和错误隔离测试；
- URL、标题、内容指纹去重测试；
- 同一事件多来源聚合、错误合并和拆分测试；
- 来源等级、排序和预测市场不影响可信度测试；
- 缓存命中、24 小时回退、90 天清理和证据保留测试；
- API 筛选、分页、错误及兼容测试；
- 情报详情、事件详情、原文跳转和转 AI 研究端到端测试；
- 全球事件必须至少有一条可追溯证据才能公开展示；
- 数据源不可用时页面明确说明缺失范围，不能显示虚假空结果。

## 15. 完成标准

- 情报搜索不再依赖两个来源的临时拼接；
- 页面可按类型、市场、来源等级和时间筛选真实数据；
- 全球事件是有证据、版本和影响链的独立对象；
- GDELT 用于全球发现，官方/媒体证据用于事实确认，预测市场只作预期信号；
- 文章和事件均可携带稳定证据上下文进入 AI 发现；
- 缓存、保留、降级和来源健康可观测；
- 所有页面不使用 mock 数据。
