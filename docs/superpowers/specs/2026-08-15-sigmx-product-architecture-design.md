# SigmX 产品总架构设计

**日期：** 2026-08-15

**状态：** 已确认并进入实施
**上位目标：** 建立“漏斗型 Web + Financial Harness Desktop + 独立 Data Hub”的三产品架构，使 SigmX 同时具备个人用户获客、专业使用和数据变现能力。

## 1. 产品定位

SigmX 是面向个人投资者、进阶研究者和个人量化开发者的 AI 投研与金融数据平台。平台由三个可独立使用、独立收费，但共享账户、订单、权益和计量体系的产品组成：

- **SigmX Web：** 发现机会、轻量验证、内容传播、用户云资产和商业化入口；
- **SigmX Desktop：** 本地优先的 AI 投研工作台，技术定位为 Financial Harness；
- **SigmX Data Hub：** 面向 Desktop 和个人开发者的标准化金融数据服务。

产品边界的统一判断规则：

1. 需要搜索引擎收录、链接分享或即时体验的能力优先放 Web；
2. 需要本地数据、私有文件、用户密钥、长任务、重计算或持续运行的能力优先放 Desktop；
3. 公共金融数据、标准化加工结果和外部数据交付属于 Data Hub；
4. 个人账户、订单、套餐、权益、积分、设备和用量由统一云平台管理；
5. Web 不是 Desktop 的简化复制，Desktop 不是 Web 的 Electron 包装，Data Hub 不是只能被 Desktop 使用的内部接口。

## 2. 目标用户与价值主张

### 2.1 个人投资者

通过 Web 自然语言选股和个股简析发现机会，在 Desktop 中完成深度研究、持续跟踪和风险审视。价值主张是降低发现与研究门槛，而非提供收益承诺或自动交易建议。

### 2.2 进阶投资者与研究者

在 Desktop 中使用多 Agent、因子、回测、本地资料和多源数据，获得可验证、可复现、可持续运行的研究环境。

### 2.3 量化开发者

不安装 Desktop 也可以通过 Data Hub REST API、Python SDK 和 CLI 获取标准化数据，按套餐获得接口权限并按数据积分计量。

## 3. Web 产品边界

### 3.1 公开获客层

公开 Web 无需登录，支持 SEO 和链接分享。一级入口包括首页、AI 选股、行情数据、研究与发现、Data Hub、定价、客户端下载和身份入口。

首期公开页面：

- `/`：品牌价值、统一搜索和三产品入口；
- `/query/:id`：可分享的自然语言选股结果；
- `/stock/:code`：个股基础信息、延迟行情、关键指标、事件和 AI 简析；
- `/fund/:code`：ETF/LOF 基础信息和折溢价概览；
- `/research/:slug`：脱敏专题或样例报告；
- `/product/desktop`、`/product/data-hub`、`/pricing`、`/download`；
- `/docs/data-hub/*`：Data Hub 数据集、接口和 SDK 文档。

上述路由已形成公开 Web 漏斗：统一搜索由匿名 Public Research API 提供最多 10 条延迟结果；保存查询、云自选和报告快照进入个人云资产，完整专业研究继续交给 Desktop。

统一搜索支持代码/名称搜索、自然语言选股、ETF/LOF 查询、市场问题和 API 文档搜索。匿名用户可获得有限但真实的结果，不得在提供任何价值前强制注册；完整结果、保存、订阅和后续研究需要登录。

### 3.2 登录后的轻量研究空间

登录后默认进入 `/me`，不能直接落到纯账户设置页。`/me` 管理用户的云端业务资产：

- 今日概览；
- 云端自选；
- 保存的查询与查询历史；
- 云端报告及摘要；
- 云任务状态；
- 通知与订阅；
- Desktop 连接状态和“在客户端继续研究”。

### 3.3 账户和商业化中心

`/account/*` 只管理个人商业关系与安全设置：套餐、研究积分、数据积分、订单、激活码、Data Hub 控制台、用量、设备、通知和账户安全。支付、API Credential 和完整设备管理不在 Desktop 重复实现。

### 3.4 Web 非目标

首期 Web 不实现完整 AlphaForge、完整 Agent 工作台、因子实验、回测、盘中持续监控、私有文件研究、本地数据源配置、模型密钥配置和实盘交易。

## 4. Desktop：Financial Harness

### 4.1 产品表达

- 面向个人用户的品类：**AI 投研工作台**；
- 面向专业用户的表达：**Financial Agent Workbench**；
- 技术定位：**SigmX Financial Harness**，即金融智能体运行与治理环境。

Financial Harness 将数据、模型、工具、Agent、上下文和治理约束装配在统一运行环境中，使研究不止是一次性问答，而成为可验证、可复现、可持续运行的工作流。

### 4.2 核心能力

- **Agent Runtime：** 多 Agent 编排、并行、辩论、风险否决、裁决和任务恢复；
- **Data Runtime：** 本地行情库、用户数据源、Data Hub 和质量元数据；
- **Tool Runtime：** 选股、行情、新闻、事件、因子、回测、基金套利和文件解析；
- **Context Runtime：** 自选、持仓、风险偏好、历史研究、私有资料和当前市场状态；
- **Governance：** 权限、研究积分、数据积分、设备授权、预算和人工确认；
- **Observability：** 数据来源、证据链、调用成本、运行过程、失败降级和结果版本。

### 4.3 功能结构

Desktop 包含研究中心、市场工作台、量化实验室、跟踪与监控、本地资产和云连接。现有 AlphaForge、基金套利、因子、回测、市场情报和风险页面逐步按该结构收口，不在首个实施阶段大规模重写视觉界面。

### 4.4 运行模式

- **Standalone：** 用户自带数据源与模型能力，本地存储和计算，云端不可用时仍能工作；
- **Connected：** 通过设备授权连接统一账户，使用 Data Hub、云端权益和必要的跨设备云资产。

客户端不得要求用户复制长期产品令牌。设备授权采用短期访问令牌、可轮换刷新令牌和服务端撤销机制。本地密钥、券商授权、持仓、文件和完整本地报告默认不上传。

### 4.5 安全执行等级

Harness 对外部动作采用固定等级：`Read`、`Propose`、`Simulate`、`Approve`、`Execute`。默认能力停留在前三层；任何真实交易必须另行设计，并经过显式授权、风险规则、人工批准和完整审计。本设计周期不实现真实交易执行扩展。

## 5. Data Hub 产品边界

### 5.1 产品定位与入口

Data Hub 可独立于 Desktop 销售，服务两条主路径：Desktop 用户获取稳定云数据；个人开发者通过 API、SDK 和 CLI 集成。

数据产品按权限组组织：

- `basic.v1`：交易日历、证券列表、行业和指数成分；
- `market.v1`：股票、指数、基金行情和复权数据；
- `finance.v1`：财务、估值、分红和公司行动；
- `pro.v1`：资金、事件、批量数据和 SigmX 加工数据。

具体接口归属和积分价格由服务端版本化目录管理，前端与 SDK 不得硬编码套餐中文名或价格。

### 5.2 差异化能力

Data Hub 的销售价值不是简单转售上游原始数据，而是多源降级、统一证券代码与字段、复权和交易日处理、去重、质量校验、缺失与异常标注、数据版本和 SigmX 加工指标。

### 5.3 Data Hub 控制台

控制台提供套餐开通、API Key、数据集权限、接口文档、在线调试、SDK 示例、用量、数据积分、请求日志、错误日志和预算告警。

### 5.4 凭证

- Desktop 和个人开发者统一使用绑定个人账户的 `sxd_live_` Credential；
- Credential 可命名、轮换、吊销，并限定 Scope、到期时间和 IP 白名单；
- 密钥明文仅在创建或轮换时展示一次；
- 所有凭证最终进入统一的权限、限流、积分和审计链路。

## 6. 套餐、权益和双积分

### 6.1 商品结构

- `Free`：公开体验、基础本地能力、基础 Data Hub 接口和少量月度数据积分；
- `Desktop Pro`：完整专业工作台，附赠基础 Data Hub 配额；
- `Data Developer`：面向 API 用户的标准数据集和开发者额度，不强制购买 Desktop；
- `Pro Bundle`：Desktop Pro 与更多 Data Hub 权限、额度的主推组合；
旧 Data Hub Key、旧请求次数配额和企业套餐不做兼容映射，统一按当前接口权限组与 Data Credit 模型执行。

### 6.2 稳定权益键

```text
desktop.device_limit
desktop.connected_mode
cloud_ai.enabled
cloud_ai.concurrent_jobs
reports.cloud_history
datahub.enabled
datahub.dataset_groups
datahub.monthly_credits
datahub.rate_limit_per_minute
datahub.concurrent_limit
datahub.max_rows_per_request
datahub.history_depth_days
datahub.commercial_use
```

### 6.3 双积分

- **研究积分：** 用于托管模型、AlphaForge、云 Agent、AI 报告和其他推理任务；
- **数据积分：** 用于 Data Hub API、批量数据、加工数据和 Desktop Connected 数据访问。

两类积分使用独立批次、余额和流水。套餐可同时发放两种积分，但一次数据请求不能消耗研究积分，一次 AI 任务也不能隐式消耗数据积分，除非产品明确把两项成本分别展示并分别入账。

### 6.4 Data Hub 扣费规则

一次调用必须同时满足接口权限、数据积分余额、速率、并发和最大返回量限制。基础元数据可设为零或极低积分；标准行情、财务、资金、高频、批量和加工数据按成本分级；批量接口按返回行数、日期跨度或数据量阶梯计费。

- 参数错误、未授权、限流、服务端异常和全部上游失败不扣分；
- 成功交付后原子扣费，空结果默认不扣费；
- 分页按成功返回页计费；
- 具有同一幂等键的重试不得重复扣费；
- 套餐数据积分按自然月发放并月底清零；
- 额外购买的数据积分包有效期为 12 个月；
- 补偿积分有效期由运营配置；
- 扣减顺序为最早到期批次优先；
- 套餐降级后余额不消失，但失去权限的接口不能仅凭积分调用。

响应返回实际积分成本、剩余积分和重置时间。用户可为 API Key 设置每日预算，并在 50%、80% 和 100% 阈值接收通知。

## 7. 统一云平台与数据归属

共享领域对象包括 `User`、`Plan`、`EntitlementGrant`、`CreditLot`、`CreditTransaction`、`Order`、`Device`、`ApiCredential`、`UsageRecord`、`CloudWatchlist`、`SavedQuery` 和 `ReportSnapshot`。所有对象直接归属个人 `user_id`，不引入组织或成员层。

数据归属：

| 数据 | 权威位置 | 默认同步规则 |
|---|---|---|
| 用户、套餐、订单、权益、积分 | 云端账户平台 | Web 和 Desktop 通过 API 访问 |
| 公共金融数据与公共加工结果 | Data Hub | Web 和 Connected Desktop 只读 |
| 云端自选、保存查询、报告摘要 | 云平台 | 登录用户跨端同步 |
| 持仓、券商授权、本地文件和模型密钥 | Desktop 本地 | 默认不上传 |
| 完整本地报告和回测 | Desktop 本地 | 用户主动分享或提交云任务时上传副本 |
| Standalone 行情库 | Desktop 本地 | 不回传 Data Hub |

## 8. 核心用户闭环

### 8.1 Web 到 Desktop

自然搜索或分享内容进入 Web，用户完成查询和简版验证，登录保存结果，然后通过安全深链或下载入口在 Desktop 中继续深度研究和持续跟踪。

当前实现采用一次性研究任务票据：Web 调用 `POST /api/cloud/handoffs` 创建最长 10 分钟有效的 `sxrh_` 票据，服务端只保存 SHA-256 哈希；深链固定为 `sigmx://research/<ticket>`，不携带查询正文、身份令牌或本地信息。Electron 只接受该严格白名单格式，Desktop 使用未撤销设备的 `sigmx-product` JWT 调用 `POST /api/cloud/handoffs/{ticket}/consume`，成功后票据立即失效，安全载荷只在渲染进程内存中存在并预填至 Agent 研究入口。

### 8.2 Web 到 Data Hub

开发者查看数据产品和文档，在线试调后注册，获取免费数据积分，创建 API Key，完成首次成功调用，随后因接口、额度或商业授权需求升级套餐。

### 8.3 Desktop 到 Data Hub

Standalone 用户在数据不稳定、缺少数据源或需要特色数据时发起设备授权，Connected 模式自动获取短期产品令牌，并可在 Web 查看和升级额度。

### 8.4 结果传播

Desktop 报告只有在用户主动选择后才生成脱敏、不可变、可撤销的 Web 快照。访问者可以基于快照发起相似查询，形成新的 Web 获客入口。

AlphaForge 报告查看器已提供“发布 Web 快照”操作。对话框不会自动复制完整报告，用户必须单独填写并确认公开标题与不超过 2,000 字的脱敏摘要；云 API 的请求模型只有 `title` 和 `summary`，发布后返回公开 slug，用户可在 `/me` 查看并撤销。

## 9. 技术架构约束

第一阶段保持 FastAPI、React、Electron 和现有 SQLite 领域存储，不立即微服务化。通过模块、接口和独立数据所有权建立边界，达到横向扩展条件后再把云端商业与计量存储迁移到 PostgreSQL。

- 公开 Web 需要 SSR 或静态生成能力，登录 Portal 可以保持 SPA；
- Desktop 使用独立路由壳与本地数据访问层；共享领域类型和视觉组件，不共享所有页面状态；
- 云 API 是 Desktop 获取身份、权益和 Data Hub 数据的唯一正式通道；
- Data Hub 先鉴权，再检查数据集权限、速率、并发、预算和积分；
- 积分扣减、用量记录和业务响应通过预授权/结算或幂等事务保证一致性；
- 数据响应携带来源、更新时间、质量状态、版本和是否降级等元数据；
- Web 到 Desktop 使用白名单深链和一次性任务标识，不向网页暴露本地服务令牌；
- 旧 `sx_` API Key 和旧请求次数配额直接失效；历史研究积分与新的 Data Credit 分账保留。

## 10. 异常、降级和安全

- Data Hub 上游失败时执行现有多源降级链；所有来源失败则不扣分；
- Desktop 云端不可用时继续运行 Standalone 能力，不把陈旧数据标记为最新；
- Connected 额度耗尽时明确提示，可由用户切换到自有数据源；
- 未登录 Web 查询在登录后恢复，不要求用户重复输入；
- 分享被撤销后返回明确的失效状态，不泄漏原报告；
- API Key 和激活码只存哈希，明文仅在创建时展示；
- 订单、权益发放、积分发放、扣费、退款和设备撤销都有幂等键与审计记录；
- 任何本地私有内容上传前必须展示范围并获得用户主动确认。

## 11. 运营后台

运营后台覆盖个人用户、商品与价格、订单与退款、激活码、权限组、双积分调整、设备、接口目录、接口积分价格、Data Hub 调用成本与质量、内容专题、样例报告、热门查询和完整转化漏斗。管理员的任何积分、订阅、凭证和设备变更均写入不可变审计日志。

## 12. 指标体系

北极星指标为：**每周完成至少一次有效研究行为的用户数**。有效行为包括有效选股、收藏标的、保存查询、阅读完整报告、在 Desktop 完成深度研究或通过 Data Hub 成功获取有效数据。

辅助指标：

- Web：有效结果率、匿名到注册、注册到保存、注册到下载、分享获客和 SEO 收录；
- Desktop：安装到首次研究、任务完成率、Connected 启用率、周活和 30 日留存；
- Data Hub：注册到首次成功调用时间、活跃 Key、积分消耗率、接口错误率、升级率和数据成本；
- 商业：套餐转化、Bundle 渗透、续费、积分包收入和毛利。

## 13. 实施拆分

总架构必须拆成可独立验收的子项目，按以下顺序实施：

1. **产品导航与边界收口：** `/me` 与 `/account` 分离，完善 Web、Portal、Desktop 三类路由壳和产品入口；
2. **Data Hub 计费基础：** 数据积分类型、版本化接口目录、接口权限组、调用预估、幂等扣费和响应配额头；
3. **Data Hub 开发者控制台：** API Key、文档、在线调试、用量、日志、预算和告警；
4. **Web 增长入口：** 统一搜索、自然语言选股、个股/基金公开页、保存查询和 SEO；
5. **Desktop Harness 收口：** 统一工具契约、上下文、运行记录、治理状态和 Connected 数据访问；
6. **跨端研究闭环：** 云自选、Web 查询到 Desktop、报告摘要和脱敏分享；
7. **个人商业化完善：** 支付、续费、个人预算告警、账单与数据消费洞察。

每个子项目必须有自己的实施计划、测试闭环和可独立部署的验收结果，不允许一次性重写全部产品。

## 14. 第一阶段验收

第一阶段仅实施“产品导航与边界收口”，验收标准为：

1. 浏览器访问公开页面时不加载 Desktop 工作台导航；
2. 登录后的浏览器默认进入 `/me`，能看到业务资产和产品状态，而不是直接进入账户设置；
3. `/account/*` 仅承载套餐、双积分、订单、用量、设备、安全和 Data Hub 管理；
4. Desktop 登录后进入 `/app`，继续访问完整专业工作台；
5. Web 访问 Desktop-only 路由时跳转 `/me`，并显示“在客户端打开/下载”的明确入口；
6. 顶部产品导航能区分 AI 选股、Desktop 和 Data Hub 三个产品；
7. 现有注册、登录、个人账户页面和 Desktop 研究页面保持可用，旧 Data Hub 鉴权与企业套餐除外；
8. 路由、导航和端模式判断具备自动化测试。

## 15. 非目标
