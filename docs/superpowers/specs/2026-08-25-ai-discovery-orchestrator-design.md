# AI 发现研究任务编排器设计

## 目标

把 AI 发现从“固定模板筛选器”升级为可完成一轮 Web 投研的任务编排器。用户输入自然语言目标后，应在运行前看到系统理解出的研究范围、指标条件、比较基准、数据可用性和执行计划；运行后获得可比较、可复核、可继续收窄的结果。

第一版不承诺通用大模型研究。它只执行本地数据能够可靠支持的六类条件，并对无法执行的条件明确降级或阻止运行：估值、分红、成长、盈利质量、现金流、行业比较与历史分位。

## 成功标准

- 用户能在一次页面会话内完成“提问、确认、运行、理解结果、继续研究”。
- 登录跳转后恢复原问题、模板和已确认条件。
- 每个解析出的条件都有 `supported`、`degraded` 或 `unavailable` 状态。
- 不把未理解的财务问题降级为“名称或行业匹配”。
- 运行前展示数据日期、覆盖范围和替代条件；不可执行时提供可操作的修正方案。
- 结果默认展示排序、评分、行业对比、主要证据、淘汰原因和风险，而不是只纵向罗列证券。
- 后端只返回有证据支持的结论，数据缺失不会被当作满足条件。

## 产品流程

### 1. 研究输入

首页保留一个主输入框，但将左侧“研究模板”改为“研究起点”。模板用于填入完整自然语言问题，不再只填入关键词。输入框下方提供可见的能力提示：估值、分红、成长、盈利质量、现金流、行业比较、历史分位。

### 2. 研究计划预检

点击“生成研究计划”后调用新的预检接口，不立即创建任务。服务端返回：

- 研究对象与市场范围；
- 已解析条件；
- 每项条件的指标、运算、周期、基准和状态；
- 数据集、最新日期、覆盖率；
- 建议排序规则；
- 执行步骤；
- 无法执行条件的原因和可选替代项。

确认弹窗改成可编辑的计划面板。用户可以删除条件、接受替代项、修改阈值和排序。存在 `unavailable` 条件时禁止直接运行，但允许“一键采用可执行版本”。

### 3. 任务执行

确认后创建研究任务。前端展示真实步骤状态：解析、数据扫描、派生指标计算、行业基准计算、候选筛选、证据核验、结果保存。第一版任务仍可同步执行，但 API 和 UI 按可异步扩展的状态模型设计。

### 4. 结果与继续研究

结果页顶部先回答“找到什么、为何值得看、哪些条件未完全满足”。主体依次为：

1. 候选比较表：综合分、排名、关键指标、行业分位、数据完整度。
2. 单家公司证据：趋势、同行基准、估值分位、异常提示、数据来源。
3. 未入选样本摘要：按淘汰原因聚合数量。
4. 数据与方法说明：用户可读的数据源名称、日期、口径、延迟和覆盖率。
5. 下一步操作：追加条件、排除公司、改变排序、保存模板、使用当前问题再次研究。

## 后端设计

### 研究计划模型

新增 `ResearchPlan`，核心字段：

- `question`
- `scope`
- `conditions[]`
- `ranking[]`
- `datasets[]`
- `steps[]`
- `executable`
- `suggested_question`

`conditions[]` 包含 `id`、`metric`、`label`、`operator`、`value`、`period`、`benchmark`、`status`、`reason` 和 `alternatives`。

新增 `POST /api/research/plans`。它只做解析与能力预检，不扣研究积分、不写研究结果。`POST /api/research/tasks` 接收已确认计划，并在服务端重新校验，避免客户端伪造支持状态。

### 条件注册表

使用集中式指标注册表替代散落的关键词判断。每个指标声明：

- 支持的自然语言别名；
- 数据字段或计算函数；
- 可用运算符；
- 所需历史窗口；
- 数据源与日期字段；
- 缺失值策略；
- 是否支持行业基准与历史分位。

第一版指标：`pe_ttm`、`pb`、`dividend_yield`、`revenue_growth`、`profit_growth`、`roe`、`operating_cashflow`、`cashflow_profit_ratio`、`market_value`。历史或行业数据不足时，计划必须标为降级或不可用，不能静默忽略。

### 执行与评分

执行器先构造统一证券研究行，再计算派生指标、行业中位数和历史分位。每个候选保存：

- 条件判定结果；
- 原始值、基准值和分位；
- 数据日期、来源和完整度；
- 综合分及其分项；
- 风险与异常。

综合分只用于排序，不能替代硬性条件。硬性条件失败的证券进入淘汰原因统计，不进入候选列表。

## 前端设计

- `LandingPage` 拆成输入区、研究起点、能力范围、计划面板、运行进度和最近研究组件。
- 登录前将待执行计划保存在 session storage；登录成功后恢复并回到计划确认态。
- 研究计划面板使用清晰的状态标签，不用数字编号表达含义。
- `ResearchResultPage` 改为“结论摘要 + 比较表 + 证据详情”，默认折叠长列表。
- 来源名称做用户可读映射，例如将 `local_market_store` 显示为“SigmX 本地市场数据快照”，同时保留技术来源供详情查看。
- 桌面宽屏优先；本轮不投入移动端适配。

## 错误与降级

- 认证失效：保存未提交的计划，登录后恢复。
- 数据集缺失：运行前提示并给出可执行替代项。
- 运行中数据变化：结果绑定数据快照日期，任务完成后不自动覆盖。
- 部分证券数据缺失：从硬条件候选中排除，并计入“数据不足”淘汰原因。
- 服务端失败：保留问题和计划，提供重试与调整条件入口。
- 不允许用空结果掩盖能力不足；能力不足与真实零候选必须使用不同状态。

## 实施边界

第一阶段完成研究计划预检、登录恢复、能力状态、可执行条件编辑和失败恢复；使用现有数据可可靠支持的指标。

第二阶段补充多期财务数据计算、行业中位数和历史估值分位，并升级结果比较表。

第三阶段接入情报搜索与投研 Skills，让候选结果能够继续生成公告、新闻和研报证据，但不在第一版运行链路中强依赖外部服务。

## 测试

- 单元测试：中文条件解析、指标注册、运算符、时间窗口、行业基准、替代项。
- API 测试：计划可执行性、任务二次校验、认证、幂等、数据不足与零候选差异。
- 前端测试：模板到计划、条件编辑、不可执行提示、登录恢复、运行步骤、结果比较。
- 端到端测试：固定执行至少四条问题——低估值高股息、现金流改善、行业盈利质量、混合支持/不支持条件。
- 回归测试：现有最近研究、结果详情、证券详情和账户菜单链路。
