# Web AI 分析聊天界面设计

## 目标

把 Web 端 `/` 的“AI 发现”从研究表单改为面向普通用户的聊天式 AI 分析页面。视觉与交互参考桌面端现有智能体，但不复制桌面端的交易运行时、复杂目标管理或系统配置。

本阶段仅调整前端界面和前端状态编排，不新增或修改后端接口。

## 用户体验

页面由两部分组成：左侧对话历史和右侧当前分析。

左侧包含“新建分析”、历史搜索入口、今天与更早的对话列表。数据优先使用现有研究任务列表；没有历史时展示空状态。移动端默认隐藏，通过按钮抽屉打开。

右侧顶部只展示“SigmX AI 分析”和面向用户的能力说明，不展示模型名称、Provider、API 地址、最大轮次等底层信息。

主区域使用聊天时间线表达完整研究流程：

1. 用户问题以用户消息显示。
2. 生成研究计划时，AI 先返回自然语言确认和研究计划卡片。
3. 执行研究时，数据读取、筛选、核验等步骤显示为可折叠的分析进度卡片。
4. 完成后，摘要、候选标的、关键指标、风险与证据入口显示为结果消息卡片。
5. 底部输入框始终可见，并提供少量基于当前上下文的追问建议。

## 现有能力融合

保留当前 `LandingPage` 已有的数据流：

- `getDiscovery` 获取研究起点和市场状态。
- `createResearchPlan` 生成计划。
- `createResearchTask` 启动分析。
- `waitForResearchTask` 与 `listResearchEvents` 更新进度。
- `getResearchResult` 获取结果。
- `listResearchTasks` 提供对话历史。

不把计划、进度和结果放在独立工作区；它们都映射为聊天消息中的结构化卡片。

桌面端 `Agent` 仅作为交互参考，并优先复用其通用聊天视觉组件。桌面专属的 SSE 会话协议、文件上传、Goal、Swarm、交易授权和停止开关不进入本阶段。

## 组件边界

- `LandingPage`：保留数据请求与研究阶段编排，改为组合聊天页面。
- `AIAnalysisShell`：负责历史栏、页头、聊天区和输入区布局。
- `AIAnalysisTimeline`：把当前问题、研究阶段和结果组合成时间线。
- `AnalysisProgressCard`：展示用户可理解的分析步骤，不泄露内部工具参数。
- `AnalysisResultCard`：展示摘要、候选标的和结果入口。
- `ConversationHistory`：使用现有研究任务数据展示历史，支持选择和新建。

组件只接收展示所需的数据和回调，不直接调用 API。

## 状态映射

- `idle`：欢迎语、快捷问题和空输入框。
- `planning`：显示用户问题与“正在理解问题”。
- `plan`：显示 AI 回复和可调整、可确认的研究计划卡片。
- `running`：显示步骤进度与当前分析状态。
- `done`：显示结果卡片，并允许继续追问。
- `error`：错误作为 AI 消息呈现，提供重试和修改问题操作。

市场数据加载失败不占据页面顶部；它显示为聊天区内的轻量提示，并允许用户继续输入不依赖该数据的问题。

## 响应式设计

- 桌面端：左侧历史栏约 220px，右侧聊天区自适应。
- 平板和手机：历史栏改为抽屉，聊天区占满宽度。
- 输入框固定在聊天区底部，消息区域独立滚动。
- 结果候选卡片在窄屏下由三列降为单列。

## 非目标

- 不增加新的聊天后端或新的会话协议。
- 不把匿名研究升级为无限自由对话。
- 不展示模型、Provider、Token、数据表名或内部工具调用参数。
- 不实现桌面端交易、文件、Swarm 和 Goal 功能。
- 不修改平台导航、情报搜索、全球事件、Skills、套餐等其他页面。

## 验证

- 为六种研究状态添加组件测试。
- 验证生成计划、确认运行、失败重试和结果跳转回调。
- 验证历史任务显示、新建分析和移动端历史栏开关。
- 验证页面中不出现模型名称或 Provider 技术信息。
- 运行前端类型检查和相关 Vitest 测试。
