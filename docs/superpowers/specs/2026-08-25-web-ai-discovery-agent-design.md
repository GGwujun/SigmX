# Web AI 发现智能体改造设计

## 目标

将 Web 端“AI发现”从关键词/正则筛选器升级为真实 AI 投研入口，复用桌面端已经存在的 `AgentLoop`、工具调用、Skill 与流式事件能力，同时保留 Web 端已经形成的“输入问题 → 确认研究计划 → 运行研究 → 查看证据与完整结果”产品链路。

本次只建设研究能力，不包含影子账户、券商连接、持仓、订单、模拟或实盘交易、交易授权与收益跟踪。

## 产品原则

1. AI 负责理解、规划、工具选择和报告归纳；确定性代码负责数据获取、数值计算、约束校验和来源记录。
2. 用户必须先看到可编辑的研究计划，再启动耗时研究。
3. 每个结论必须能追溯到工具结果、Data Hub 接口或明确标注的候补数据源。
4. 模型密钥与供应商配置只对管理员可见，普通用户不能携带或查看平台密钥。
5. 模型不可用时明确失败或降级为基础筛选，不得把规则结果伪装成 AI 结果。

## 用户链路

### 1. 提出问题

AI发现首页继续使用当前主输入框和研究主题入口。研究主题只负责填充一个完整问题，不显示无含义的数字，也不独立于输入框形成第二套入口。

### 2. AI 生成研究计划

服务端调用配置的“规划模型”，把问题转换为结构化计划：

- 研究目标与市场范围；
- 待验证条件和指标口径；
- 推荐使用的 Skills；
- 所需 Data Hub 数据集与候补源；
- 执行步骤；
- 缺失能力、风险和预计耗时。

现有规则解析器继续运行，用于校验模型输出中的字段、操作符和可执行性。模型不能声明系统不存在的数据能力。

### 3. 用户确认

用户可编辑研究范围、条件和排序。不可执行条件必须显示原因，并允许删除或替换；不得静默把用户问题改写为“低估值高股息”。确认后创建研究任务。

### 4. Agent 执行

Web 研究执行器复用桌面端 `AgentLoop` 的研究子集：

- 允许：读取 Data Hub、调用公开候补源、加载投研 Skills、计算、检索新闻/公告/研报、生成证据和报告；
- 禁止：任何账户、持仓、券商、订单、交易 Mandate、交易执行及影子账户工具；
- 每次任务使用服务端平台模型配置，不读取用户本地桌面配置；
- 运行过程写入持久化任务和事件表，支持刷新后恢复、取消和失败重试。

### 5. 进度与结果

前端使用 SSE 展示面向用户的阶段事件：理解问题、准备数据、调用 Skill、计算指标、交叉验证、形成结论。隐藏模型思维链，仅展示工具名称、数据来源、完成状态和可安全公开的摘要。

结果页包含：

- 结论摘要；
- 候选标的或主题判断；
- 关键指标与比较；
- 证据卡片及来源时间；
- 使用过的 Skills 和数据源；
- 数据缺口、冲突证据与风险；
- 研究参数、生成时间和模型标识；
- 继续追问、调整计划后重跑、导出报告。

结果页不出现交易按钮、影子账户、持仓或收益模块。

## 系统架构

### Web Research Orchestrator

新增独立的 Web 研究编排服务，负责：

- 规划模型调用与结构化输出校验；
- 将确认计划转换为 Agent 研究目标；
- 创建隔离的研究工具白名单；
- 接收 Agent 事件并映射为 Web 研究事件；
- 持久化任务、证据、报告与用量；
- 处理取消、重试、超时和幂等。

编排服务依赖现有 `ChatLLM`、`AgentLoop`、Skill Runtime 和 Data Hub 客户端，不复制桌面端 UI 或交易运行时。

### 研究工具白名单

采用显式白名单而不是黑名单。只有研究数据、搜索、计算、Skill 和报告工具可以注册到 Web Agent。测试必须证明账户、券商、持仓、订单、Mandate、live runner 和 shadow account 工具不可见且不可调用。

### 数据与证据

Data Hub 为第一数据源；Skill 清单声明的免费源仅在 Data Hub 缺失、超时或覆盖不足时使用。每条证据记录来源、接口/Skill、查询参数摘要、数据时间和候补原因。最终报告引用证据 ID，不直接信任模型生成的数值。

### 持久化模型

沿用现有研究任务主表，并补充：

- 结构化 AI 计划及版本；
- Agent session/run ID；
- 阶段事件；
- Skill 与数据源调用记录；
- 证据与结论引用关系；
- 模型供应商、模型名、Token 用量、耗时和错误分类。

旧规则研究结果继续可读；新任务标记执行模式为 `agent`，规则降级任务标记为 `rules_fallback`。

## 运营后台 AI 配置

运营后台新增“AI 能力”分组，拆为四个页面：

1. 模型供应商：供应商、Base URL、可用模型、启停、连接测试。
2. 模型策略：规划/执行/总结模型、温度、Token 上限、超时、重试和降级顺序。
3. API 密钥：服务端加密保存、只显示掩码、支持更新/停用/连通性测试和审计；接口永不回传明文。
4. 数据源：Data Hub 与候补源的启停、优先级、市场覆盖、健康状态和降级规则。

配置变更要求管理员权限并写入审计日志。运行任务保存配置快照，后续修改不改变历史结果解释。

## API

- `POST /api/research/plans`：改为 AI 规划并返回校验后的结构化计划；模型不可用时返回明确模式与降级说明。
- `POST /api/research/tasks`：根据已确认计划异步启动 Agent 任务。
- `GET /api/research/tasks/{id}`：返回任务状态与当前阶段。
- `GET /api/research/tasks/{id}/events`：SSE 事件流，支持事件游标和断线续传。
- `POST /api/research/tasks/{id}/cancel`：取消运行。
- `POST /api/research/tasks/{id}/retry`：从失败阶段创建一次受控重试。
- `GET /api/research/tasks/{id}/result`：返回报告、候选、证据、来源、风险与运行元数据。
- `/api/admin/ai/*`：供应商、策略、密钥、数据源与健康检查管理接口。

所有研究任务接口要求登录；计划接口可允许有限匿名试用，但不得泄露平台配置。

## 错误与降级

- 未配置模型：计划页提示“AI 服务尚未配置”，管理员可从错误进入后台配置；不展示伪 AI 结果。
- 模型调用失败：按后台策略重试或切换供应商，并记录实际使用模型。
- Data Hub 不可用：仅在计划允许时使用候补源，并在结果中显著标记。
- 部分数据缺失：保留已完成证据，结果状态为“部分完成”，不生成无证据结论。
- Agent 超时或取消：持久化已有事件和证据，可安全重试。
- 输出校验失败：要求模型修复一次，仍失败则终止，不执行未经校验的计划。

## 安全

- 平台密钥只保存在服务端加密存储中，不进入前端、日志、SSE 或研究报告。
- 工具参数与结果经过现有敏感字段脱敏。
- Web Agent 采用研究工具白名单和独立系统提示词。
- 禁止交易相关工具的路由级、运行时和测试级访问。
- 管理配置操作全部记录管理员、时间、变更摘要和原因。

## 验收标准

1. AI发现提交自然语言问题时，服务端实际发生模型调用，并在任务元数据中记录非敏感模型信息。
2. 规划结果能覆盖现金流、盈利质量、行业比较等多指标问题；系统按真实数据能力标记可执行性。
3. 任务通过 Agent 调用至少一个 Skill 或数据工具，前端实时展示阶段和来源。
4. 刷新页面后可恢复运行状态；取消、失败和重试链路完整。
5. 结果中的数值都能定位到证据记录，数据缺失时不编造候选。
6. 普通用户看不到平台密钥和管理配置。
7. Web Agent 无法发现或调用任何账户、持仓、订单、券商、交易及影子账户工具。
8. 现有 AI发现视觉语言保持一致，不直接移植桌面端聊天页面。

## 迁移顺序

1. 建设运营后台 AI 配置与加密密钥存储。
2. 抽取研究专用 Agent 工具白名单和 Web Research Orchestrator。
3. 将计划接口切换为 AI 规划 + 规则校验。
4. 将研究任务切换为异步 Agent 执行与 SSE 事件。
5. 改造 AI发现和结果页，接入真实进度、证据与追问。
6. 保留旧结果兼容读取，停止为新任务生成规则伪 AI 报告。
