# SigmX 递进式个人套餐设计

## 背景与目标

当前四档套餐按产品线横向拆分：`Desktop Pro` 提供桌面投研，`Data Developer` 提供数据接口且明确关闭 Desktop 与云端 AI。这使用户无法把套餐理解为从体验、个人研究、数据增强到专业研究的连续升级路径。

本次调整把个人套餐改为严格递进关系：后一档必须包含前一档的所有功能权限，并只提高能力范围、用量和并发上限。纯 API 商业客户不放入个人套餐梯度，未来作为企业方案单独承接。

## 套餐梯度

### 1. 免费版

- 价格：免费。
- 定位：完成注册后的产品体验。
- 权益：基础数据集、每月 1,000 Data Hub 用量、50 点一次性 AI 研究体验用量、1 个 AI 并发、1 台 Desktop 设备、1 年历史数据。
- 限制：不含云端报告历史，不允许商业使用。

### 2. Desktop Pro

- 价格：268 元/季。
- 定位：个人日常投研工作台。
- 包含免费版全部功能。
- 权益提升：完整 Desktop Connected 模式、每月 300 AI 研究用量、每月 10,000 Data Hub 用量、2 个 AI 并发、5 年历史数据、云端报告历史。
- 设备数保持 1 台。

### 3. Data Pro

- 对外名称由 `Data Developer` 改为 `Data Pro`；内部代码继续使用 `data_developer`，保证历史订单、激活码、统计和外键兼容。
- 价格：398 元/季。
- 定位：需要标准化行情、财务接口和批量分析的进阶研究者。
- 包含 Desktop Pro 全部功能，不再关闭 Desktop 或云端 AI。
- 权益提升：开放 `basic.v1`、`market.v1`、`finance.v1` 数据集；每月 700 AI 研究用量；每月 100,000 Data Hub 用量；3 个 AI 并发；5 个接口并发；10 年历史数据；2 台设备。

### 4. Pro Bundle

- 价格：518 元/季。
- 定位：重度个人研究和批量任务。
- 包含 Data Pro 全部功能。
- 权益提升：增加 `pro.v1` 数据集；每月 1,200 AI 研究用量；每月 150,000 Data Hub 用量；4 个 AI 并发；10 个接口并发；20 年历史数据；3 台设备。

## 继承约束

套餐顺序固定为：`free < desktop_pro < data_developer < pro_bundle`。

对所有布尔能力，后一档不得从 `true` 退回 `false`。对数据集权限，后一档集合必须包含前一档集合。对用量、并发、行数、历史深度和设备数，后一档数值不得低于前一档。该约束由自动化测试验证，防止运营或后续开发再次制造断层。

`datahub.commercial_use` 四档均保持 `false`，因为它不是个人套餐的递进权益。商业使用、SLA、团队席位和定制数据属于未来企业方案。

## 数据与兼容策略

### 目录代码

四个稳定 code 不变：`free`、`desktop_pro`、`data_developer`、`pro_bundle`。只调整 `data_developer` 的显示名称、价格、描述和权益，因此历史订单无需改写。

### 新数据库

更新 `catalog.py` 的规范种子，所有新数据库直接生成新梯度。

### 已有数据库

当前 `_seed_catalog` 只补缺失套餐，不会更新既有记录。本次增加一次性、幂等的目录迁移：

- 仅当 `data_developer` 仍匹配旧版官方名称、价格或旧版“关闭 Desktop/AI”特征时，升级为 Data Pro。
- 同步四档官方权益到新的递进基线。
- 已完成的订单继续保留购买时的快照，不追溯修改金额。
- 当前有效订阅按新目录获得不低于原有的权益；Data Developer 用户属于纯增益升级。
- 不修改管理员手工创建的其他套餐 code。

## 页面设计

### 公共定价页

定价页从四张独立商品卡改为一条从左到右的升级梯度：

- 每张卡显示“包含上一档全部权益”。
- 只强调相对上一档新增或提高的核心权益，避免每张卡重复十几行配置。
- Data Pro 标记“进阶推荐”，Pro Bundle 标记“最高配置”；不同时出现多个主推荐。
- 卡片下方增加完整横向权益对比表，布尔、集合和数值均按同一行比较。
- 标题明确为“从体验到专业研究，权益逐级增加”。

### 套餐与权益页

- 当前套餐卡显示中文名称，不直接暴露 `pro_bundle` 等内部 code。
- 展示当前档位在四级梯度中的位置。
- AI 研究、Data Hub、设备、数据集和历史深度统一归入“当前套餐权益”。
- 激活码仍在本页处理；激活更高档后刷新全部权益。

### 运营后台

- 套餐列表按 `sort_order` 展示。
- Data Developer 历史统计映射为 Data Pro 显示名，内部 code 不变。
- 套餐编辑时提示“后一档不得低于前一档”，服务端保存校验不允许破坏继承关系。

## API 与错误处理

现有 `/api/catalog/plans` 响应结构保持不变，避免前端和客户端协议升级。显示名、价格、描述和权益由服务端目录返回。

若目录违反继承约束，管理端保存返回 422，并指出具体套餐与权益键；公共目录仍返回最后一次有效配置。迁移必须在同一数据库事务中完成，失败时整体回滚。

## 测试与验收

- 目录单元测试验证价格顺序、套餐名称和逐键继承关系。
- 数据库迁移测试覆盖旧官方目录升级、重复执行幂等、历史订单快照不变。
- 设备、Data Hub 和 AI 权限测试改为验证 Data Pro 包含 Desktop Pro 能力。
- 定价页测试验证升级文案、唯一推荐标记和 Data Pro 的完整继承。
- 套餐与权益页测试验证中文名称和统一权益展示。
- 浏览器验收四档顺序、视觉层级、登录后管理入口及激活后的刷新链路。

## 不在本次范围

- 在线支付和自动续费。
- 企业商业授权、团队席位、SLA 和合同定价。
- 修改历史订单成交金额。
- 删除或重命名内部 `data_developer` code。
