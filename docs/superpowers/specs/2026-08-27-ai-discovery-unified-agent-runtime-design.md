# AI 发现统一智能体运行时设计

日期：2026-08-27

## 1. 背景与目标

当前 Web「AI 发现」使用独立的 `ResearchAgentRunner`：最多执行 8 轮，只能调用市场检索和 Skill 元数据加载两个工具，Skill 不能作为真实工作流执行，也没有客户端智能体已有的持续上下文、多智能体、文件和完整事件能力。

本次改造复用客户端成熟的 `AgentLoop` 执行核心，建立面向 Web 的 `ResearchAgentRuntime`。两端对齐执行模型，但保留不同的产品边界：客户端是本地开放研究工作台；Web AI 发现是云端托管、只读、安全、证据可追溯的研究智能体。

本次不修改客户端运行逻辑，不开放交易、账户、影子账户、Shell 或服务器任意文件能力。

## 2. 原则与方案

采用“共享 AgentLoop + Web 专用适配层”，不扩充第二套简化循环，也不直接暴露客户端 SessionService。

1. 一个执行核心：Web 和客户端共享 `AgentLoop`。
2. 能力由策略授予：Web 使用显式工具白名单，不能只依赖提示词约束。
3. 研究可验证：数值结论引用本次任务证据，并展示日期、来源、模型、Skill 与工具轨迹。
4. 复杂度按需升级：简单问题使用单智能体，复杂问题才启用研究小组。
5. 降级透明：模型不可用时可做规则分析，但必须标记为非 AI 降级结果。
6. 兼容现有链路：保留计划、确认、任务、事件和结果 API，替换内部执行器。

## 3. 总体架构

新增 `ResearchAgentRuntime` 作为 `AgentLoop` 与 Web 研究任务之间的适配层：

```text
AI 发现页面 -> 研究计划与确认 -> ResearchOrchestrator
  -> ResearchAgentRuntime
       -> AgentLoop
       -> ResearchToolPolicy / 研究工具注册表
       -> ResearchSkillsLoader
       -> 可选 Research Swarm
       -> ResearchContext / 文件工作区
       -> EvidenceCollector
  -> ResultAssembler / EvidenceValidator
  -> 结果页与后续追问
```

适配层负责构造研究上下文、加载平台模型配置、建立工具白名单、转译执行事件、收集证据和组装结构化结果，不复制循环逻辑。

## 4. 运行流程与状态

1. 用户输入问题，系统生成可编辑研究计划。
2. 用户确认后创建持久化任务并进入队列。
3. 运行时依据问题、计划和历史上下文判断复杂度。
4. 单智能体或研究小组执行检索、计算、比较、反向验证和结论整理。
5. 工具调用产生标准证据，重要事实绑定证据 ID。
6. 输出组装器校验结论引用、数据日期和必需字段。
7. 页面呈现报告，允许继续追问、追加条件或从当前上下文重跑。

状态统一为 `planned -> queued -> running -> validating -> completed`，异常状态为 `failed`、`cancelled` 和 `degraded`。`degraded` 不得显示为正常 AI 完成。

## 5. 执行轮次与预算

- 默认最多执行 50 轮，与客户端 `AgentLoop` 对齐。
- 达到 80% 时触发收敛提示，优先补齐证据并输出结论。
- 同时限制任务超时、Token、工具调用和多智能体预算。
- 最大轮次是运营后台可配置的平台默认值，可按套餐限制，但用户不能突破平台上限。
- 取消信号必须传递到主循环和所有子智能体。

## 6. 工具策略

新增 `ResearchToolPolicy` 和 `build_research_registry()`。运行时直接从允许集合构建注册表。

允许：Data Hub 目录和只读查询；行情、估值、财务、公告、新闻、宏观和行业数据；计算、比较、时间序列分析和只读回测；研究目标、证据账本、受限文件解析、报告产物和研究专用多智能体入口。

永久禁止：下单、撤单、券商连接、Mandate、账户、持仓、订单、影子账户、Shell、后台进程、任意系统命令、任意服务器文件读写、Skill 写入修改，以及未被平台显式允许的远程 MCP 工具。

每次运行持久化“实际授予工具”和“实际调用工具”，页面据此展示当前工具。

## 7. Skills

`ResearchSkillsLoader` 从平台 Skill 库加载用户选择或计划匹配的 Skill，将完整方法、参数约束、允许的数据端点和输出要求注入 Agent。Skill 只能指导 Agent 调用本次已授予的工具，不能绕过工具策略。

若 Skill 依赖的数据源不可用，任务执行前说明缺失能力；存在允许的免费后备源时可以降级，但结果必须标记。任务记录 Skill 版本、来源、使用原因、声明端点、实际端点和降级情况。

## 8. 多智能体

`ResearchSwarmRouter` 只在跨数据域、多公司深度比较或明确要求多角度审查时启用研究小组。首期官方角色为基本面、行业与可比公司、新闻事件、风险与反向证据、主研究员。简单筛选和单指标查询保持单智能体。

子智能体继承相同工具白名单、任务预算和证据协议，不能获得额外权限。

## 9. 上下文与文件

每个任务保存原问题、确认计划、消息摘要、工具轨迹、Skill、证据、结果和追问。追问创建关联运行并复用有效上下文；过期数据必须重新查询。

只允许用户显式上传的 PDF、CSV、XLSX、JSON 和文本文件。文件位于任务隔离目录，只读解析并限制类型、大小和生命周期。Agent 不可访问目录外文件。系统可生成 Markdown、CSV、XLSX 和 PDF 产物，通过受控接口下载。

## 10. 输出协议

版本化输出至少包括：执行模式 `ai` 或 `rules_degraded`、摘要、结论、候选标的、关键指标、证据 ID、反向证据、风险、数据来源和日期、模型、Skills、工具、智能体、执行完整度、警告和下载产物。

`EvidenceValidator` 拒绝未知或跨任务证据引用。缺少证据的重要结论只能显示为待验证提示。规则降级结果使用相同外壳，但必须显示降级原因。

## 11. 前端交互

保留“输入问题—确认计划—运行研究—查看结果”主链路，增加由真实事件驱动的执行面板：

- 运行流程和当前阶段；
- 最大轮次与已用轮次；
- 被授予及实际调用的工具；
- 已加载及实际使用的 Skills；
- 多智能体成员和状态；
- 历史上下文继承情况；
- 文件上传、解析和产物下载；
- 实时证据、警告、阶段结果和最终输出。

未启用的能力显示原因，而不是静态“已支持”。结果页提供继续追问、追加条件、基于当前证据重跑和下载报告。

## 12. API 与兼容

保留现有任务创建、查询、取消、事件和结果端点。任务详情扩展 `runtime` 字段，包含限制、工具、Skills、多智能体、上下文、文件和输出状态。新增追问/派生运行、文件上传与产物下载、运行时能力以及版本化事件和输出 Schema。

旧任务继续可读，新字段采用可空值和 Schema 版本；页面将旧数据标记为“旧版研究记录”。

## 13. 错误与可观测性

- 模型、数据源、Skill、工具和子智能体使用不同错误码。
- 可恢复的数据源错误可切换受控后备源，但不能静默处理。
- 事件流断开后可从任务详情恢复；服务重启后按幂等策略恢复或明确失败。
- 日志记录任务 ID、运行 ID、模型、工具耗时、证据数和预算，不记录密钥或用户文件内容。
- 运营后台展示成功率、降级率、平均轮次、数据源错误和模型成本。

## 14. 分阶段迁移

1. 建立运行时、工具策略、输出 Schema 与契约测试。
2. 用 `AgentLoop` 替换 orchestrator 内的简化 Runner，保持现有 API。
3. 接通真实 Skill、证据账本、事件和结果组装。
4. 增加上下文追问与受限文件能力。
5. 接入受控研究小组和运营指标。
6. 移除简化 Runner，保留旧任务读取兼容层。

每阶段均保持现有 AI 发现主链路可运行，不做不可回退的一次性切换。

## 15. 测试与验收

后端测试覆盖工具禁用、单/多工具、超过 8 轮、取消、超时、预算收敛、Skill 实际执行与越权拦截、多智能体权限、证据校验、降级标记、任务恢复、追问上下文和文件隔离。

前端测试覆盖计划确认、执行、取消、失败恢复、完成、追问、真实事件面板、多智能体状态、文件、产物、降级视觉区分和旧任务兼容。

核心验收问题为“寻找经营现金流持续改善、盈利质量高于行业中位数的 A 股公司”。系统必须执行真实财务和行业数据查询，给出候选或明确数据缺口，每个数值结论可定位证据，并支持追问“只保留近三年没有重大处罚的公司”。页面必须能查看实际模型、Skills、工具、轮次、数据日期和输出完整度，不能以内置存储名称充当结论。

## 16. 完成标准

- Web AI 发现实际运行 `AgentLoop`，不再依赖 8 轮简化 Runner。
- 流程、轮次、工具、Skills、多智能体、上下文、文件和输出均由真实后端状态驱动。
- Skill 能参与真实执行并受 Data Hub 与工具策略约束。
- AI 结果与规则降级结果严格区分。
- 客户端逻辑和配置不受影响。
- 禁止能力通过自动化安全测试。
- 核心端到端案例通过。
